# Day 4: Automate the first factory job

## Ticket

**Title:** Validate imported pull request links against their GitHub identity

As an engineer importing a pull request, I want Ghostline to accept only source links that match the imported GitHub repository and revision, so every displayed link remains trustworthy evidence.

Acceptance criteria:

- The imported PR URL uses HTTPS on `github.com` and matches the response owner, repository, and PR number.
- Each commit URL uses HTTPS on `github.com` and matches the response owner, repository, and commit SHA.
- Mismatched and off-host links are rejected at the Zod API boundary.
- Tests cover valid links and host, repository, PR-number, and commit-SHA mismatches.
- Valid GitHub responses keep the existing import and timeline behavior.

## Trigger and workflow

The local Codex schedule invokes `.agents/skills/ghostline-ready-issue/SKILL.md` every two hours. Scheduled runs use the repository's normal `gh` CLI and Git remotes; they do not run `gh auth status` as a preflight, change authentication, or switch accounts, and they report the exact failure if a read-only operation is denied. Before worktree creation, local `origin/main` is refreshed from the public HTTPS URL and must match the SHA GitHub publishes. The skill searches open issues labeled `ready-for-agent` oldest first, treating the maintainer-applied label as explicit approval. Issues from untrusted authors are skipped. An open PR suppresses an issue only when its author is trusted, it explicitly links the exact issue, and its changes or description address the ticket's acceptance criteria; a bare reference or unrelated PR does not suppress work. It selects at most one eligible issue and requires an explicit `Hackathon Day: N` field. A persistent per-day Git ref is claimed with `scripts/day-lock.sh` before removing the issue label; overlapping runs compete to update the same ref. The lock is held through PR creation and released by moving the ref back to its saved idle SHA. Unexpected termination can leave a lock commit that requires human verification and recovery. New PRs carry the day marker and issue link. The skill reads the acceptance criteria and `AGENTS.md`, then works in an isolated branch/worktree. It follows DDD/TDD and allows at most one focused repair for a confirmed check failure and one for confirmed Qodo findings. It runs the configured checks locally, pushes the verified branch with `git push -u origin BRANCH` (never forced), and opens the PR with `gh pr create` only after checks pass; it never merges. If there is no eligible issue, it exits without changes. If GitHub access, Qodo review, requirements, or checks are blocked, it reports the blocker and stops. Reapplying the label is a human-controlled retry after reviewing the blocker.

The lock lives at `refs/heads/ghostline-automation/locks/day-N`: an idle ref points at a saved base commit; a held ref points at a lock commit whose message reads `Ghostline automation lock day N run RUN_ID`. `day-lock.sh` acquires it with `git push --force-with-lease=<ref>:<observed-idle-sha>` (an empty expected SHA when the ref does not exist yet), so GitHub rejects a claim if the ref moved after it was observed. Release verifies the owned SHA and run ID, then restores the saved idle SHA with another lease; the ref is never deleted. The helper is covered by a local bare-remote concurrency test and Warden's pre-commit gate. That test does not prove GitHub's server behavior or the scheduled shell's permissions, and this path has not yet been exercised by a scheduled run. A lock left by an earlier version of the script (`lock for day N, run ID`) is also treated as held. The skill reports and preserves a lock after unexpected termination rather than guessing whether it is stale.

The scheduled entry point is runner-agnostic: `bash .agents/skills/ghostline-ready-issue/scripts/run-pickup.sh` sends the same prompt (`scripts/prompt.md`) to `codex exec` or `claude -p`. `GHOSTLINE_AGENT_RUNNERS` sets the order (default `codex claude`). The next runner is tried only when the previous one stopped on a usage-limit or authentication error; any other failure ends the run so a second agent never repeats half-done work. One run at a time is enforced with a lock in `GHOSTLINE_RUN_LOG_DIR` (default `~/.ghostline/runs`), where each run's log is kept. Claude runs with `--permission-mode dontAsk` and an explicit tool allowlist; Codex runs in a `workspace-write` sandbox with network enabled and the worktree directory added. `scripts/test-run-pickup.sh` checks fallback, ordering, and overlap with stub binaries; it does not call a model, so neither real runner invocation has been exercised yet. To schedule it with launchd on macOS, fill in `scripts/com.ghostline.pickup.plist.example` (`__REPO__`, `__HOME__`), save it as `~/Library/LaunchAgents/com.ghostline.pickup.plist`, and load it with `launchctl bootstrap gui/$(id -u) <that file>`; unload it with `launchctl bootout gui/$(id -u)/com.ghostline.pickup`. It runs every two hours and does not run at load. Run only one scheduler at a time: pause the Codex automation when scheduling this script with cron or launchd.

The schedule is local and does not use a hosted model API key or GitHub Actions agent runner. GitHub Actions remains responsible for hosted CI and Nox checks. The `ready-for-agent` label is removed at pickup so later runs do not repeat the same ticket.
